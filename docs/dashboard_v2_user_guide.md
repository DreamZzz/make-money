# Dashboard V2 产品使用手册

> 适用版本：Dashboard V2  
> 使用对象：个人散户、有限资金账户、中低频周/月调仓  
> 核心目标：每天收盘后，用最少步骤判断“今天能不能决策、要不要调仓、怎么执行、执行后如何复盘”。

---

## 0. 在你开始之前

这套系统不是“神奇荐股器”，而是一套本地化的纪律执行工具。它的价值在于把数据更新、选股、资金约束、风险检查和复盘固定成流程，降低情绪化交易。

### 0.1 这套系统能为你做什么 / 不能做什么

| 类型 | 内容 |
|---|---|
| 能做 | 自动完成日终数据检查、市场阶段/热度判断、生产信号、统一资金池约束、纸交易、组合体检和信号收益复盘 |
| 能做 | 给出市场阶段+热度的专业判读，并据此给 T+1 增减总仓位的建议（目标权益仓位） |
| 能做 | 在权益预算内按相对强弱动态搭配指数基金（沪深300/中证500/恒生科技） |
| 能做 | 在数据异常、模型不可用、风险过高时阻止你继续调仓 |
| 不能做 | 让你一夜暴富，或保证每年正收益 |
| 不能做 | 保证主动选股跑赢指数——实测 2024-2026 牛市里现有主动策略都跑输了中证500，所以个股选股目前只作研究/shadow，不占主仓 |
| 不能做 | 让你完全不用判断，尤其是基金申赎、现金安排和异常处理 |
| 不能做 | 替你真实下单，Dashboard V2 只做纸交易和手动执行规划 |

它背后的投资哲学（2026-05 战略调整后）：**现阶段以指数为核心**——先判断市场处于什么阶段、有多热、贵不贵，据此决定权益仓位高低，再用相对强弱把仓位搭配到领先指数；主动个股选股因为尚未证明可信超额（Alpha158 选股 IC 接近 0），降级为研究/shadow，等市场分化或风格翻转再观察。系统的价值不是预测每一笔交易，而是：① 用市场状态引擎给纪律化的择时与搭配，② 用信号收益跟踪和竞赛系统诚实地判断哪个策略真的值得信任、什么时候该上。

### 0.2 你应该预期什么

| 维度 | 合理预期 |
|---|---:|
| 年化超额收益 | 3-8%，对比沪深 300 / 中证 500 / 恒生科技等核心指数 |
| 单年最大回撤 | 20-25% |
| 看到效果所需时间 | 12 个月以上 |
| 任意 3 个月短期跑输概率 | 约 35% |
| 单周操作频率 | 通常 0-5 次，极端时期可能更多但会被换手率约束 |
| 最适合的资金 | 10 万元以上更顺畅；5 万元可用但会频繁遇到一手门槛 |

不要用单周或单月盈亏评价系统。更合适的观察窗口是 6-12 个月，重点看是否在可承受回撤内持续跑赢基准，以及执行偏差是否越来越少。

### 0.3 什么情况下应该停止跟单

| 停止条件 | 动作 |
|---|---|
| 连续 6 个月跑输基准 >= 5 个百分点 | 暂停新增 BUY，只保留风险管理和复盘 |
| 连续 3 个 `daily_close` 失败且未修复 | 暂停调仓，先修数据/任务链路 |
| 半年内有明确用钱需求 | 降低仓位或退出，不要让投资系统和现金需求冲突 |
| 生产模型监控出现 CRITICAL 且持续未解决 | 不跟 Alpha158 新信号，只做组合体检 |
| 你无法坚持每周复盘 | 暂停使用；这套系统依赖持续纪律，不适合完全放任 |

## 1. 一句话理解 V2

Dashboard V2 不是研究报表集合，而是一个“收盘到调仓驾驶舱”。

它把原来散落在 Streamlit 里的行情、信号、资金池、指数基金、组合风险和任务状态，重新整理成一条操作动线：

```text
收盘后检查 → 生成建议 → 风险确认 → 手动执行 → 纸盘/收益复盘
```

你每天不需要先想“我要打开哪个技术页面”。默认先打开 **今日行动**，系统会告诉你下一步该做什么。

### 1.5 第一次使用：从零到首次调仓

首次使用不要急着一次买满。先让系统跑通，再逐步把真实账户和纸盘对齐。

| 问题 | 建议 |
|---|---|
| 最低多少资金值得用？ | 5 万元可以试用，但一手门槛会卡住很多 A 股；10 万元以上体验明显更好 |
| 已有持仓怎么处理？ | 不建议立刻清仓重来；先导入或记录当前持仓，让系统在组合体检里识别风险 |
| 第一次信号是否一次性买齐？ | 不建议。第一次只执行高置信度、预算内、无冲突的 30-50%，观察 2-4 周 |
| 资金档位怎么选？ | `small` <= 10 万，`medium` 10-50 万，`large` >= 50 万；小资金会限制持仓数量并提示一手资金缺口 |
| 启动后第几天信号可以信？ | 等至少 1 次完整收盘闭环 + 1 次开盘纸交易成功后，再开始参考；冷启动前只看数据健康 |
| 要不要同步真实账户？ | 先纸盘跑一周，确认 Dashboard、资金、持仓和信号逻辑都看懂，再小额跟随 |

第一次完整流程：

1. 启动 Dashboard V2。
2. 打开 `/health`，确认数据、模型、定时任务状态。
3. 打开 `/today`，看系统推荐下一步。
4. 打开 `/rebalance`，只关注 `可执行` 和 `需人工确认`。
5. 手动执行前，确认资金缺口、一手门槛、冲突信号。
6. 执行后回 `/portfolio`，检查现金、持仓和风险警告。

## 3. 最重要的安全原则

V2 首期只做“安全写入”，不会替你真实下单。

允许的操作：

- 查看真实数据、信号、资金池、风险和任务状态
- 记录现金流
- 记录指数基金持仓快照

不允许的操作：

- 从 Dashboard V2 启动收盘闭环、开盘纸交易或研究任务
- 直接切换 production 模型
- 手动改信号状态
- 真实证券账户下单
- 绕过风控规则强行交易

所有写入都会记录到 `dashboard_audit_log`，包括时间、动作、payload 摘要、结果和错误信息。

### 3.1 安全与隐私

默认数据都保存在本机 DuckDB：`/Users/zhaoqiang/Documents/Project/make-money/data/duckdb/market.db`。Dashboard V2 不会向外部服务上传你的持仓、现金流、信号或纸交易记录。AkShare、yfinance、Baostock 等只作为行情/财务/成分股下载数据源使用。

移动端查看只适合做复核，不适合做高压下单决策。当前默认部署是本机电脑日终使用；如果必须远程访问，优先使用可信 VPN 或 SSH tunnel，并避免把 `5173` 或 `8600` 直接暴露到公网。

## 4. 一级模块怎么用

### 4.1 今日行动

入口：

```text
/today
```

这是默认首页，也是每天收盘后第一个看的页面。

你只需要看三件事：

1. 顶部 Health Ribbon 是否显示“数据可用”。
2. “本轮操作 / 需要现金 / 预计耗时 / 买入减仓”是否合理。
3. 主按钮显示什么。

主按钮含义：

| 按钮 | 含义 | 你该做什么 |
|---|---|---|
| 查看任务状态 | 还没有生成完整决策上下文，或最近任务需要确认 | 去“市场与数据健康”查看定时任务状态 |
| 查看调仓计划 | 数据和计划已就绪 | 进入“调仓执行” |
| 等待数据更新 | 数据或任务状态阻塞 | 不要调仓，先看“市场与数据健康” |
| 查看组合体检 | 暂无操作项 | 检查风险和收益复盘 |

右侧 **证据口径** 会显示数据日期、信号日期、模型版本和成本口径。如果这些日期不是同一天，或者模型版本为空，先不要执行调仓。

### 4.2 调仓执行

入口：

```text
/rebalance
```

这里把 Core 指数基金和 Satellite 个股放在同一张执行视图里。

表格分三段：

| 分组 | 含义 | 操作建议 |
|---|---|---|
| 可执行 | 在预算和规则内，可以进入纸交易/执行计划 | 优先处理 |
| 需人工确认 | 通常是基金申赎、现金操作或需要手动判断的项 | 看原因后手动确认 |
| 暂缓 | 信号暂停、估值不合适、预算不足或规则不通过 | 默认不操作 |

页面里的几个关键概念：

| 字段 | 解释 |
|---|---|
| 层 | `Core` 是指数基金底仓，`Satellite` 是个股策略仓 |
| 金额 | 本次预计买入/赎回/减仓金额 |
| 预算占用 | 这条动作会消耗多少 core 或 satellite 预算 |
| 资金缺口 | 当前现金不够覆盖计划时显示的缺口 |
| 冲突信号 | 同一股票同时出现 BUY/SELL 等方向冲突 |
| 一手门槛 | 买入一手所需资金，用来判断小资金账户是否容易跳过 |

执行顺序建议：

1. 先看顶部资金缺口。
2. 再处理 `可执行`。
3. 然后看 `需人工确认`，特别是基金 REDUCE/BUY。
4. `暂缓` 默认不要手动强行执行。
5. 如果出现冲突信号，优先不做，等下一轮信号确认。

### 4.3 组合体检

入口：

```text
/portfolio
```

这个页面回答：“我现在的组合有没有明显风险？”

重点看：

- 总资产、现金、持仓、回撤
- 风险警告数量
- 持仓行业、市值、估值字段覆盖
- 当前持仓列表
- 信号收益跟踪摘要

风险警告的优先级：

| 风险 | 说明 |
|---|---|
| Top5 集中度过高 | 少数持仓占比太大，容易被单票波动拖累 |
| 最大行业过高 | 组合可能无意识重仓一个行业 |
| PE/PB 覆盖不足 | 估值数据缺失，基本面判断可信度下降 |
| 未知行业占比高 | `stock_info.industry` 覆盖不够 |
| 持仓数量不适合资金档位 | 小资金过度分散或大资金过度集中 |

如果风险警告很多，不建议只看信号买卖。先控制组合结构，再考虑新增仓位。

#### 如何读信号收益跟踪

信号收益跟踪来自 `signal_outcomes`，它是判断策略是否值得继续信任的核心反馈。

| 指标 | 健康区间 | 怎么看 |
|---|---:|---|
| T+5 `alpha_vs_benchmark` | > 0 | 信号发出后约一周相对基准的超额收益，适合看短期执行质量 |
| T+20 `alpha_vs_benchmark` | > 0 | 信号发出后约一个月相对基准的超额收益，更适合判断策略有效性 |
| raw return | 不单独设门槛 | 原始收益只能说明有没有赚钱，不能说明是否跑赢市场 |
| hit rate | 50-60% 正常，低于 45% 要警觉 | 命中率不是越高越好，关键是平均超额为正 |
| model_name | 分模型对比 | 观察 `trend` / `mean_rev` / `industry_rotation` / `alpha158` 谁在贡献超额，连续为负的模型需要降权、暂停或重训 |

经验判断：

| 场景 | 解释 |
|---|---|
| Alpha158 的 20 日 alpha 持续为正 | production 模型目前仍有贡献 |
| Alpha158 alpha 持续接近 0，但其它模型为正 | production 模型可能需要重训或降权 |
| 所有模型 alpha 都转负 | 先怀疑市场环境或数据/执行问题，不要急着加仓 |
| 命中率低于 45% 且持续 1 个月 | 降低操作频率，等待下一轮模型评估 |

### 4.4 市场温度计

入口：

```text
/market
```

这是“以指数为核心”阶段最重要的判断页：今天市场处于什么阶段、有多热、贵不贵，应该拿多少权益仓位，钱该搭配到哪个指数。

重点看：

| 区块 | 含义 | 怎么用 |
|---|---|---|
| 专业判读 | 一句话综合阶段+宽度+热度+估值+相对强弱 | 当天市场的总体定性，先看这句 |
| 阶段 / 趋势分 | 强势上升/温和上升/震荡整理/弱势整理/下跌/危机（-100~100） | 阶段决定基准仓位，越强仓位越高 |
| 热度分 | 0-100，50=常态，>70 过热，<30 冰点 | 过热谨慎追高，冰点可逆向 |
| 宽度 | %站上年线(MA200)、当日上涨家数 | 上涨但宽度低=“贵且窄”，要警惕普涨退化为少数股拉指数 |
| 估值分位 | 全A股 PE/PB 近10年分位 | >70 分位=偏贵，<30=偏低 |
| T+1 仓位建议 | 目标权益仓位 + 加仓/减仓/维持 | 这是核心动作信号：把总仓位往目标靠 |
| 指数搭配 | 各指数基金的目标权重（相对强弱轮动） | 在权益预算内超配领先指数、低配走弱指数 |
| 趋势图 | 趋势分 / 热度分近期走势 | 看市场是在转强还是转弱 |

关键纪律：**仓位由阶段决定、只在“下跌/危机”才大幅降仓**。系统刻意长期偏多，估值贵/宽度差/过热只小幅下调（不会因为牛市回调就吓得空仓），避免在上涨行情里踏空。

### 4.5 市场与数据健康

入口：

```text
/health
```

这个页面不是给你浏览行情，而是判断“今天的数据能不能用于决策”。

重点看：

- 最新行情日期
- 定时任务是否执行
- 数据源任务是否失败
- 字段覆盖率：`industry / market_cap / pe_ttm / pb`
- Qlib production 模型是否可用
- 最近 job 的步骤和失败诊断

处理原则：

| 状态 | 处理 |
|---|---|
| 数据可用 | 可以继续看调仓计划 |
| 数据需确认 | 看字段覆盖率和任务日志，谨慎执行 |
| 任务失败 | 不要调仓，先修任务 |
| 模型不可用 | 不使用 Alpha158 信号，只看其它辅助信息 |

如果顶部全站 Health Ribbon 显示阻塞，优先来这个页面找原因。

### 4.6 研究实验室

入口：

```text
/research
```

这里收纳高级研究能力，不是日常操作的第一入口。

适合查看：

- 当前 production 模型
- 最近 Qlib 实验
- IC / RankIC / ICIR 摘要
- PortAna artifact 状态
- 跳转旧 Streamlit 研究工作台

普通周频调仓时，不建议从研究实验室开始。只有在你要判断模型是否失效、是否需要切换模型或做策略复盘时，再看这里。

### 4.7 策略竞赛

入口：

```text
/tournament
```

把多个虚拟账户（每个是一套完整可部署配置：模型组合 + 套利门槛 + 配比 + 风险档）放在相同行情下并行对标，用历史回放预热出 2 年以上的可比战绩，再选最优去指导实盘。

重点看：

| 区块 | 含义 |
|---|---|
| 竞赛榜 | 各账户的年化/超额 alpha/Sharpe/最大回撤/换手/命中率/平仓笔数，按超额排名 |
| 晋级闸门 | 是否有账户够格晋级实盘；含选择偏差守卫（N 选 1 的冠军需明显优于亚军，不只是运气） |
| 参赛账户 | 各配置的订阅模型与状态，冠军会标“实盘候选” |

诚实提醒：首跑（2024-2026）所有主动配置都跑输中证500、且回撤更大，晋级闸门正确地推荐“冠军=None”。**这正是竞赛系统的价值——用证据拦住你把钱投进跑输指数的主动策略**。目前主动选股全部 shadow，等闸门真正达标再上。

## 5. 每天收盘后的标准流程

### Step 1：打开今日行动

```text
http://localhost:5173/today
```

先看顶部是否为“数据可用”。如果不是“数据可用”，不要直接去调仓执行。

### Step 2：按主按钮走

如果按钮是“查看调仓计划”，进入调仓执行。

如果按钮是“查看任务状态”，说明收盘闭环还没产出完整上下文，或者最近任务需要确认。Dashboard V2 不负责启动任务，只去“市场与数据健康”查看定时任务状态和异常诊断。

如果按钮是“等待数据更新”，暂停操作。

### Step 2.5：看市场温度计定仓位

进入 `/market`，先读“专业判读”那句，确认今天的市场阶段、热度和估值水位，再看 **T+1 仓位建议**：

- 目标权益仓位告诉你总仓位该拿多少（其余为现金），这是“以指数为核心”阶段最重要的动作信号。
- 看指数搭配，把权益按相对强弱倾斜到领先指数。
- 记住纪律：阶段不恶化（没到下跌/危机）就别大幅降仓，避免在上涨里踏空；过热/偏贵只小幅减。

### Step 3：检查操作量

在今日行动页确认：

- 本轮操作多少次
- 需要多少现金
- 预计耗时多少分钟
- 买入/减仓数量是否异常

经验规则：

| 情况 | 建议 |
|---|---|
| 操作 0 次 | 不调仓，只做组合体检 |
| 操作 1-5 次 | 正常周频范围 |
| 操作 6 次以上 | 检查是否换手过高或信号冲突 |
| 需要现金大于可用现金 | 先处理资金缺口 |

### Step 4：进入调仓执行

先看 `可执行`，再看 `需人工确认`，最后看 `暂缓`。默认不要执行暂缓项。暂缓通常意味着系统认为现在不适合操作。

### Step 5：手动执行

系统不会真实下单。你需要在券商或基金平台手动执行。

执行时建议记录：

- 实际成交/申赎日期
- 实际金额
- 成交价格或基金份额
- 是否和计划有偏差

### Step 6：执行后复盘

执行后回到：

```text
/portfolio
```

确认：

- 现金是否符合预期
- 持仓是否更新
- 风险警告是否增加
- Core/Satellite 是否明显偏离

## 6. 每周复盘流程

建议每周固定一次，通常是周五收盘后或周末。

1. 看今日行动，确认本周是否有操作。
2. 看调仓执行，确认哪些信号被执行、哪些暂缓。
3. 看组合体检，检查风险警告和持仓集中度。
4. 看信号收益跟踪，确认最近信号是否真的有效。
5. 看研究实验室，只关注 production 模型和 IC/ICIR 是否恶化。

### 本周复盘的量化门槛

如果出现以下量化条件，应降低操作频率，优先复盘而不是继续加仓：

| 信号 | 警惕门槛 | 建议动作 |
|---|---:|---|
| 60 日滚动 ICIR | 较基线下降 50% 且持续 2 周 | 暂停新增 Satellite BUY，等待重训或新实验 |
| 暂缓比例 | > 60% 且持续 2 周 | 检查预算、停牌、涨跌停、估值规则和一手门槛 |
| 信号冲突数 | 每周 >= 3 且持续 2 周 | 降低规则策略权重，优先看 arbiter 决策，不手动猜方向 |
| 纸盘落后基准 | 30 日累计落后 >= 5pp | 暂停扩仓，复盘成交偏差、成本和模型告警 |
| 严重风险警告 | CRITICAL >= 2 个且持续 3 天 | 停止 BUY，优先处理集中度、现金和数据质量 |

## 7. 常见状态怎么处理

### 顶部显示“数据可用”

可以继续看调仓计划。

但仍要确认右侧证据口径：

- 数据日期是否为最新交易日
- 信号日期是否为最新交易日
- 模型版本是否存在
- 成本口径是否正常

### 顶部显示“任务失败”

不要调仓。去：

```text
/health
```

查看失败步骤、命令和日志摘要。修复后重新跑收盘闭环。

### 调仓计划里很多“暂缓”

这不一定是坏事。

常见原因：

- 估值不合适
- 资金不够买一手
- Core/Satellite 预算不允许
- 信号冲突
- 数据覆盖不足

暂缓项默认不要强行执行。

### 出现资金缺口

说明当前现金不足以覆盖计划。

处理顺序：

1. 先看是否有 REDUCE 或赎回项。
2. 如果没有，减少低优先级买入。
3. 不要为了执行全部信号而破坏现金安全垫。

### 模型版本为空

说明 Qlib production 模型不可用。此时不要依赖 Alpha158 信号，先修模型状态或只做风险观察。

### 7.5 异常场景应急

| 场景 | 处理方式 |
|---|---|
| 出差 3 天回来 | 不补做历史调仓；从今天最新 `/today` 重新开始。旧信号可能已经过期 |
| `daily_close` 连续失败一周 | 停止调仓，先看 `/health` 的失败步骤；修复后跑完整收盘闭环，再恢复观察 |
| 券商账户资金冻结或停牌 | 纸盘继续记录理论动作，但真实账户按可交易资金执行；下次复盘时记录偏差 |
| 真实账户与纸盘不一致 | 不要硬追纸盘；先手动记录现金流/基金快照，让账户重新对齐 |
| 换电脑或重装系统 | 迁移项目目录，重点保留 `data/duckdb/market.db`、`config/`、`output/`、`models/`，再重新启动 V2 |
| Dashboard 打不开 | 先跑 `scripts/run_dashboard_v2.sh`，看 API 8600 和前端 5173 是否都启动 |
| 开盘/收盘定时任务没执行 | 到 `/health` 查看定时执行历史；若连续漏跑，优先修调度器，不手动猜信号 |

## 9. 术语速查

| 术语 | 门外汉一句话 | 经验值范围 |
|---|---|---|
| Core | 指数基金底仓，用来拿市场平均收益和稳定账户 | 通常 50-70% |
| Satellite | 个股策略仓，用来争取超额收益 | 通常 30-50% |
| Core/Satellite 资金池 | 一个账户里给基金和个股分别设预算，避免互相抢钱 | 偏离过大时先再平衡 |
| satellite_budget | 个股策略本轮还能用多少钱 | BUY 只能在预算内排队 |
| Health Ribbon | 页面顶部的数据健康条 | 不是“数据可用”就不调仓 |
| Evidence Drawer | 证据口径，告诉你数据日期、模型版本和成本口径 | 日期不一致时先停 |
| 可执行 | 规则和预算内可以执行的计划 | 仍需你手动下单 |
| 需人工确认 | 系统不能替你判断的基金/现金/特殊操作 | 看说明后再决定 |
| 暂缓 | 系统建议当前不执行 | 默认不碰 |
| IC | 模型排序和未来收益的相关性 | 0.02 算及格，0.05 算优秀，< 0 表示模型可能失效 |
| ICIR | IC 的稳定性 | > 0.3 算可投资，< 0.1 算不稳定 |
| confidence | 信号置信度，0-1 越高越可信 | 系统默认 0.75 以下不执行 |
| 一手门槛 | 买入 A 股最小 100 股需要的钱 | 小资金账户大概率被卡，建议账户 >= 10 万 |
| turnover | 换手率，代表本轮买卖占组合的比例 | 默认上限 30%/日；过高会被成本侵蚀 |
| kill_switch | 回撤过大时的硬止损 | 回撤超过 25% 会停止所有 BUY |
| alpha_vs_benchmark | 信号收益减去基准收益 | 大于 0 才说明跑赢基准 |
| hit rate | 信号命中率 | 50-60% 正常，< 45% 警觉 |

## 11. 最小可执行使用口诀

每天只记这 7 句：

1. 先打开 `/today`。
2. 顶部不是“数据可用”，就不调仓。
3. 主按钮让你去哪，就去哪。
4. `暂缓` 默认不碰，`冲突信号` 默认不做。
5. 第一次使用不要一次买满。
